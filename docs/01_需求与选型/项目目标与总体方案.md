## 1. 项目背景

实验室关节电机项目按分期推进，自研硬件研发周期长。若"等硬件到位再开发软件"，软件排期将被硬件长尾拖垮。因此确定**软件先行**策略：把完整软件栈提前开发出来，并保证硬件到位后能低成本适配。

软件先行曾走过的路：在 STM32F103 + 杜邦线 + 驱动板的粗糙平台上，底层（电机参数辨识 + 电流环/速度环）骨架已独立完成并通过运行态验收（S0~S8 标定链、Flash 双页参数固化、FOC 电流环验收四条全过），并已完整交接（该平台文档库与本库同构，见实验室项目 `docs/`）。结论同时也很明确：**杜邦线级别的供电与信号完整性无法支撑上层算法开发**——继续在该平台上开发力控/运控，调试噪声会淹没算法收益。

由此做出本项目的载体决策：采用 DengFOC V4 套件（ESP32-WROOM-32U + 官方 SimpleFOC 库 + AS5600 磁编码器 + 2208 云台电机）作为中间件与上层的**开发沙盒**——硬件投入最小化、算法开发全力化。最终自研硬件到位后，通过适配层替换完成组合适配调试，收敛为一套代码。

## 2. 项目定位与边界

> **一句话目标**：在 DengFOC V4 套件上，按工业开发标准先行完成关节电机的中间件（三环级联、有感/无感）与上层（力控、运控）算法栈；以分层契约为保证，使全部算法资产在实验室自研硬件到位后零重写平移。

### 2.1 本仓库做什么

- **中间件**：速度环、位置环（级联结构）、目标斜坡、滤波；预留无感入口
- **上层**：重力补偿、阻抗控制、轨迹规划、动力学辨识、多关节协同
- **支撑**：IMotor 契约接口、DengFOC V4 板级档案、NVS 标定固化、串口调参工具链

### 2.2 本仓库不做什么

- **不重复造底层**：电流环/参数辨识已由 STM32 底层项目完成并交接；本仓库通过适配层调用（P0 电压力矩起步；2026-09-21 起适配层默认 SimpleFOC 真电流环 MT2，TST-01 验收；P4 换实验室底层，接口不变）
- **不做契约外操作**：任何"绕过 IMotor 直接操作电压/PWM"的代码不允许合入
- **不因硬件粗糙降低软件规格**：文档、版本、验收链按工业要求执行

## 3. 工业开发规范

1. **版本管理**：git，一次提交一件事；参考资料（`v4/`、上位机工具等大体积第三方资料）不入库。
2. **文档纪律**：按 `00_文档总览.md` 的分层与台账执行；验收记录按日期命名（`YYYYMMDD_P0_主题.md`）。
3. **参数纪律**：凡进入代码的物理参数必须注明来源（规格书 / 辨识 / 官方例程），禁止拍脑袋；R/L/KT 歧义项必须在 P1 前辨识收口（登记表见 HW-DENG §3）。
4. **单位**：全库 SI（rad、rad/s、N·m、A、V），接口边界单位见 ARC-01 §5。
5. **防御**：目标限幅在 IMotor 实现内强制执行；母线欠压 11.1V 自动失使能（对齐官方保护行为）。
