## 0. 本篇只讲四条

1. **参数卡的显示是上位机本地对象值，不是固件状态**——`sendIntegralGain()` 先改本地 `pid.I` 再发命令，未连接时写入被静默吞掉；固件侧唯一可信源是读回应答或 `[VEL DBG]` 探针的 `P=/I=` 字段。**写入必读回**。[B-代码事实 + A-实测]
2. **rot 整数圈计数是测速链的零信任锚点**——相邻探针行 (rot×2π+ang) 之差/Δt 给出真实机械速度，标度类伪影骗不过整数计数。40 rad/s 档由此一锤定音。[A-实测]
3. **每个常驻参数要有"第二本账"**——存在一条用已流数据就能算的独立量纲等式（vq = KE·ω + R·iq）。本篇零新实验、仅凭这条账抓出 KT 表值虚高 2.58 倍。[A-实测]
4. **KT 定档 0.032 N·m/A**（四点稳态定标，残差 ±3%）；旧表值 0.0827 = 8.27/KV 系公式初值，因输入 KV=100 与实物不符（实测 KV_eff≈300）废弃。[A-实测]

## 1. 病情陈述

参数卡写入 I=0.0254（N=10）后：3 rad/s 方波呈停-走锯齿（EXP-05 主题）；换 40/80 rad/s 高速测试"波形紧贴目标收敛、没有任何问题"（转引实测）——但 **Vq 仅 1.4~1.8V**，与参数表 KE=KT=0.0827 V·s/rad 所需反电动势（40/80 rad/s → 3.3/6.6V）直接矛盾。同时段探针报 `I=0.0127`（boot 默认 N=5），与参数卡显示不符。

## 2. 事实链

1. 3 rad/s 阶跃（`速度环_低速3rad_s_实际N5_停走锯齿.csv`，当时以为 N=10）：56 有效拍中 46% 卡死(|v|<0.5)、32% 冲刺(v>5，峰值 13.4)、12% 贴目标带，**均值 3.06≈目标**；卡死段 Vq≈0.15~0.25V；末尾 15 拍断开冻结尾已剔除。[A]
2. 40/80 高速（`速度环_40与80rad_s_N5_Vq矛盾.csv`）：40 档 Vel 紧贴目标（σ≈1.3）、Vq 1.36~1.59V；80 档 Vel 77.7~85.8、Vq 1.45~1.84V——**目标翻倍 Vq 仅涨 ~0.2V**；两段末尾失能/断开冻结尾。[A]
3. 40 档探针验证（`速度环_40rad_s_N5_探针验证.csv` + `速度环_40档_VELDBG探针日志.txt`）：
   - 探针全程 `P=0.0025 I=0.0127`——**N=10 从未生效**；会话内 rot 连续（1764→2266）且无 [FW BOOT]，排除中途重启还原 [A]；
   - rot 计数判读：相邻探针行 (rot×2π+ang) 差/0.5s = 39.8~40.1 rad/s，与 sv 一致——**40 档为真速** [A]；
   - vq≈1.45V、Cq≈0.02A、母线 12.17V → 单点 KE=(1.45−8.25×0.02)/40 ≈ **0.033 V·s/rad** [A]；
   - 低速卡死段 Vq=I·R 对账吻合（静止无反电动势），低速结论不受影响。
4. N=10 重写并验证（`速度环_N10扫速5至40_定标.csv` + 探针）：写入六条命令回显、探针 `I=0.0254` 全程；10/20/30/40 四档稳态 (vq, sv) 最小二乘 → **vq = 0.224 + 0.0320·ω**（残差 ±0.04V ≈ ±3%；截距 0.224V ≈ R·Cq̄+死区压降，自洽）；5 档因停-走锯齿非稳态剔除。[A]
5. 源码核查 [B]：上位机 `simpleFOCConnector.py::sendIntegralGain()` 先 `pid.I = value`（本地对象）再 `setCommand('VI…')`，命令映射本身正确（SimpleFOC 2.2.1 `commands.h`：`CMD_V_PID='V'`）；`PidCard.refreshFromDevice()` 回填的正是该本地对象。`DengFocBoard.h` kt 字段注释自证："公式初值 = 8.27/KV（SI 下 Ke=KT），T-P1-4 实测收口"——**收口从未执行，值已被下游消费**。

## 3. 初始假设与误判

- **误判一：「3 rad/s 数据是 N=10 的失败证据」**。合理来源：参数卡明确显示 I=0.0254。隐含前提：卡面=固件。推翻证据：探针 I=0.0127 [A]。→ 全部低速/高速数据实为 N=5，"N=10 失败"结论作废重测。
- **误判二：「40/80 报告速度被测速链放大」**。合理来源：Vq 反电动势账在 KE=0.0827 下差 3~5 倍，且 40→80 Vq 只涨 0.2V。推翻证据：rot 整数计数证实 40 真速 [A]。→ 矛盾的真正出口不是"速度假"，是"KE 表值假"。80 档未做探针验证，降级 [D-存疑]。
- **误判三：「KT=0.0827 是①标称，可信」**。合理来源：参数来源优先级规则①官方标称优先。事实：它是公式初值（8.27/KV，KV 取官方值），且头文件注释自己承诺"实测收口"未跑——属于**未收口参数被下游消费**。[B]

## 4. 排查过程与转折点

- **转折点一：探针 P=/I= 字段**。速度环失控案（2026-09-21 早）留下的 [VEL DBG] 探针第二次立功——一行 `I=0.0127` 直接作废一整轮"N=10 失败"结论。没有探针，该误判会沉淀成"N=10 无效、直接上 N=20"的错误处方。
- **转折点二：rot 整数计数判读法**。对"速度真假"的怀疑，用圈数计数（不可能被标度伪影污染的整数量）裁决——40 档洗清、KE 单点出炉。
- **转折点三：反电动势账本**。vq=KE·ω+R·iq 三个量全部已在流，"零新实验标定"就此成立：四档各稳数秒，拟合即得 KE 与截距。
- **污染面盘账**（改参数前先盘"谁消费了它"）：
  - 免疫：电流环验收（Kp=L·ωc 不含 KT）；速度环设计意图（J 反推含同一 KT，J/KT 比值相消——数值验证 20×4.06e-6/0.032=0.00254 与旧算一致）；低速机制分析（α=KT·I/J 比值不变）；位置环设计（kpP=ωp 不涉 KT）；电流红线（A 域）。
  - 中毒：**setTorque N·m↔A 换算**（SimpleFocMotor.cpp，×2.58）；**state_.torque 读数**（×2.58）；J 绝对值与 mN·m 叙事（×0.4）；**DEFAULT_TORQUE_LIMIT**（旧 0.03 N·m 在新 KT 下折 0.94A 越过 0.5A 红线——安全连带，随抄回改 0.016 N·m）。

## 5. 根因、修复与验证

- **根因一（数据源）**：KT 公式初值未经实测收口即被下游消费；公式输入 KV=100 与实物不符（由 KE=0.032 反推 KV_eff≈300 [C-推断]）。[A+B]
- **根因二（工具链）**：上位机参数卡无写入后回读校验，卡面显示本地对象值，制造"已写入"假象。[B]
- **修复**：四点定标 KT=0.032、J_EST=4.06e-6（取值保 kpV 零漂移）、DEFAULT_TORQUE_LIMIT 0.016 N·m、N=10 定档（kiV 倍率 10.0f）——commit `ffaf7fc` 已推；setTorque/state_.torque 随 kt 常量替换自动痊愈，代码结构未动。
- **验证**：kpV 复算零漂移（已做）；重烧后 boot 打印 KT=0.0320/J=4.06e-06/ki_v=0.0254（**待执行，挂账**）；setTorque 力矩换算上机抽测（挂账）。

- **「N=10 已写入并失败」** → 探针 I=0.0127 + sendIntegralGain 本地先行的源码事实 → 当前表述：参数卡显示不构成写入证据；N=10 于当日重写并探针验证后定档。

- **「N 越大 PM=arctan(N) 越高」**（更早会话记录）→ Bode 相位与 ζ-PM 双推导 → 正确关系 PM=atan(ωx/N) 随 N 降（理论收口记 EXP-05 §2）。

## 8. 方法论与迁移用法

1. **参数第二本账**：凡常驻参数，配一条用已流数据可算的独立量纲等式做对账（本平台清单：vq=KE·ω+R·iq、T=KT·i、α=KT·I/J、Vq_lim=I_lim×R）。收口前参数禁止被 API 表面消费——本次若晚发现，P2 力控会把 ×2.58 带进产品。
2. **写入必读回**：任何在线写参数（PID/限幅/模式）后，以下一回读或探针字段为准；工具改进挂账：整定台写入后自动回读比对、不符标红。
3. **整数计数锚点**：判"模拟量标度可疑"时找整数计数器（圈数/脉冲数/事件数）裁决——标度类伪影骗不过整数。
4. **污染面盘账**：改任何常驻参数前，先列"谁消费了它"的免疫/中毒两栏表；本次盘点支撑了"只换常数、不重整定"的决策。
5. **公式初值必须带门禁**：注释里"待实测收口"的参数，收口前视同未定义——头文件自证材料（B 级）是翻案的第一手证据。
