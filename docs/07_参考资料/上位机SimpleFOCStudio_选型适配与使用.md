## 1. 选型结论与设计逻辑

**结论**：选定 SimpleFOCStudio（本地 EXE 版运行、zh 源码审计）为本项目套件平台的唯一图形化整定上位机。

设计逻辑：

1. **协议原生匹配**：固件端 SimpleFOC 自带 Commander 电机命令集，Studio 直接说这门语言——固件侧零协议改造，我们只需 StudioBridge 两行接入；
2. **整定刚需全覆盖**：四套 PID 整定页（速度 V、角度 A、电流 Q/D）+ 目标阶跃 + 实时曲线 + 启停控制，正是分环整定的标准动作；
3. **开箱即用且可审计**：EXE 免 Python 环境；zh 源码在手，协议可查证（本文 §2 即源码实证）、必要时可魔改；
4. **被否决的方案**：串口绘图器（只能看不能调）；自研上位机（造轮子，与"不重写 FOC 轮子、专注上层算法"同一条立项理由）。

**边界**：它是**套件平台的工具**。P4 换实验室硬件后，上位机随平台另定（CAN 工具链），届时本文降级为历史参考。

## 2. 协议合同（源码实证）

### 2.1 连接层

| 项 | 行为 |
|---|---|
| 串口参数 | **115200 / 8N1（已写死）** |
| 握手 | **无**——打开串口即通 |
| 连接模式 | **拉取（已写死）**——连上后把固件当前参数读进界面；命令行交互页保留"仅连接"入口供手动调试 |

### 2.1.1 命令前缀的来源链，与「两个同名框」陷阱（历史档案）

> **状态（2026-09-20 零配置改造后）**：本节降级为历史背景——前缀在 `simpleFOCConnector.py` 构造函数写死 `'M'`，`configureDevice()` 不再从 JSON 加载串口七字段，设备页「命令ID」输入框与「设置」弹窗已删除，**运行期不存在任何能改写前缀的代码路径**。当年依赖"device.json + 界面手填"的两个同名框陷阱随之根除。原排查链保留如下，供理解协议与考古。

**为什么单列一节**：这个字段是历史上最耗时的一个坑——上位机界面上有**两个**中文标签都叫「命令ID」，只有一个是真字段。填错的那个不会有任何报错，只是链路整体无声瘫痪（轮询偶通、pull config 全废、参数全零）。

前缀来源链（`src/simpleFOCConnector.py`）：

| 环节 | 事实 |
|---|---|
| 默认值 | `devCommandID = ''`（构造函数） |
| 唯一赋值来源 | `configureDevice()` 从 JSON 的 `devCommandID` 键读取 |
| 谁调用它 | **只有** `workAreaTabbedWidget.openDevice()`（菜单「文件 → 打开设备」） |
| 谁用它 | `sendCommand(devCommandID + 命令体)`（`setCommand`/`getCommand`） |
| 落盘 | `toJSON()` 写回 `devCommandID`；界面手填的值**只活在本次会话** |

⇒ 结论：**只有走「文件 → 打开设备」加载 `device.json`（其 `"devCommandID": "M"` 已就位），才是可靠、可复现的路径。**

两个同名框的鉴别：

| 界面位置 | 控件 | 写入成员 | 是否下发到串口 |
|---|---|---|---|
| 「设置」按钮弹出的 *Configure serial connection* 窗口 | `connectionIDlineEdit`（标签 `连接ID（不下发）`） | `connectionID` | **否**——全库无任何发送路径读取它，纯留档 |
| 「设备」页「连接」按钮旁的 `命令ID:` 输入框 | `devCommandIDLetter` | `devCommandID` | **是**——决定线路前缀 |

> 提示：弹窗那个字段原名 *connection name*，中文翻译成「命令ID」才产生歧义；本机源码已把标签改为「连接ID（不下发）」并加了悬浮说明。

**固件侧兜底（宽容解析，2026-09-20 增）**：即便前缀填错，`StudioBridge::handleLine()` 也会靠两条铁证自动判定本会话约定 —— 见到 `MM…` 判为「已配 ID」，见到非 `M` 打头的命令字母行判为「无 ID」，默认按已配 ID 处理，且随证据自我修正。代价是掩盖配置错误（`dbg on` 时会打印 `handleLine id=stripped/absent` 便于核对），收益是两种约定都能跑。**但这只是兜底，SOP 仍要求填对。**

### 2.2 命令层

**线缆格式 = `<命令ID><命令体>\n`**。下表按**命令 ID = `M`** 的约定直接给出线缆上的字符串（例：`ME1` = ID `M` + 命令体 `E1`；监控量查询因命令体自身以 `M` 开头，线缆上是 **`MMG0`**）；若命令 ID 留空，则线缆上就是去掉了首字符的形态（`E1`、`MG0`）。全部命令体已与固件端 `commands.h`（SimpleFOC 2.2.1）逐条比对一致：

| 功能 | 命令 | 备注 |
|---|---|---|
| 目标值 | `M2.5`（数字直跟） | 目标滑杆 |
| 启停 | `ME1` / `ME0` | |
| 控制模式 | `MC0/1/2` | 0 力矩、1 速度、2 位置（3/4 为开环变体） |
| 力矩类型 | `MT0/1/2` | 0 电压、1 dc_current、2 foc_current |
| 速度环 PID | `MVP` `MVI` `MVD` + `MVR`(ramp) `MVL`(limit) `MVF`(LPF) | 整定页"速度" |
| 位置环 P | `MAP` + `MAR` `MAL` `MAF` | 整定页"角度" |
| 电流 Q 轴 PID | `MQP` `MQI` `MQD` + `MQR` `MQL` `MQF` | 需电流采样（P1 前置） |
| 电流 D 轴 PID | `MDP` `MDI` `MDD` + `MDR` `MDL` `MDF` | 同上 |
| 限幅 | `MLU`(电压) `MLC`(电流) `MLV`(速度) | |
| 相电阻 | `MR<值>` | |
| 监控配置 | `MMD`(降采样) `MMS`(变量掩码) `MMC`(清除) | 连接时 Studio 自动下发 |
| 状态查询 | `MG0~MG6` | 应答目标/角度/速度/vd/vq/id/iq |
| 传感器零位 | `MSM`(机械 offset) `MSE`(电零位) | |
| 调制方式 | `MWC`(居中) `MWT`(0 正弦/1 SVPWM/2,3 梯形) | 我们固定 SVPWM |

### 2.3 数据判定三规则（决定固件输出格式）

上位机对收到的每行按首字符分类（`SerialPortReceiveHandler`）：

| 行特征 | 判定为 | 固件来源 |
|---|---|---|
| 以数字或 `-` 开头 | **绘图数据**（Tab 分隔） | `motor.monitor()` 输出 |
| 含 `Monitor` 字样 | 状态应答 | `MG` 查询的应答 |
| 其余 | 控制台日志 | 各类打印 |

推论：会话期间固件不得往串口打印非协议文本（我们的 shell 已让位，满足）。

## 3. 我们的适配设计

### 3.1 StudioBridge（adapter 层）

- `Commander('M' → command.motor 全权委托)`：一条通道覆盖 §2.2 全部命令；
- `monitor_variables = 目标|速度|角度`、`monitor_downsample = 0` 初始静默——连接后 Studio 自己下发 `MMD/MMS` 开流；
- **契约**：Commander/SimpleFOC 类型封闭在 adapter 层，`core/`、`control/` 零感知（P0-⑤ 编译检查）。

### 3.2 shell 让位机制

| 动作 | 方式 |
|---|---|
| 进入会话 | **自动**：shell 读到以大写字母开头、且不在自身命令字白名单里的行（= 上位机协议命令）即置会话态，并把该行转交 `StudioBridge::handleLine()`；手工输 `studio` 仍有效 |
| 会话期 | 串口收发由会话独占，shell 不再插话（不打印 `dispatch raw=`、不回「未知命令」） |
| 退出会话 | 板上复位（EN/RST）——Commander 独占后 shell 听不到命令，复位是最可靠的退出通道 |

让位的原因：两个解析器同读串口会抢字节。

两处易错细节（都在固件侧，改动见 commit `f9b07f1`）：

1. **转交必须补回行尾 `\n`**：Commander 的 `isSentinel()` 靠行尾字符判 GET/SET，而 shell 行缓冲里没有换行符；漏补会把「读」变成「写 0」（`MQP` → 参数被清成 0），是危险错误。
2. **非本会话 ID 的行静默丢弃**：`handleLine` 不认领的行直接丢，绝不回「未知命令」——这条洪流曾把串口每秒刷掉 20 行。

> 自动接管不可逆：会话态只能靠复位退回；一串纯噪声的大写行也可能触发接管（判别依据见 `SerialShell::isShellCommand_` 白名单）。

### 4.2 三环整定操作剧本（P1，对齐 SPEC-T T-P1-3/6/7）

**载体程序**：`examples/FocKit_commissioning`（examples 下唯一主程序）——建模带宽计算区（开机即算即打印增益）、`loop t|v|p|i` 一键进会话、`step` 自动方波激励。计算链（计算优先，参数来源优先级见 SPEC-T §1）：**建模 → 取标称 → 选带宽 → 公式算增益 → Studio 在计算值附近微调 → 抄回**。

> **整定台优先入口（2026-09-20 起）**：上位机默认第一页即「三环整定台」（`tuningBench.py`）——选口连接后点环按钮（电流/速度/位置）即自动完成：目标归零 → 力矩类型/控制模式 → 曲线变量/降采样 → 参数卡切换 → 开流；右侧参数卡直接读写当前环 PID，目标区提供 归零 / ±幅值 阶跃与使能。本节以下剧本的"Studio 操作"在整定台上均一步可达；原设备页手工路径（MC/MT/MMS 手发）保留为备用与排查通道。电流环幅值默认 0.15 A、超 0.5 A 持续红线标红（SPEC-T）。

**每环统一节奏**：前置检查 → 模式设置 → 增益初值（公式算，不扫参）→ 阶跃激励 → 判据核对 → 抄回代码 + 落盘。

#### 电流环（T-P1-3，前置：电流采样接入）

| 步骤 | 内容 |
|---|---|
| 前置 | T-P1-2 板载电流采样接入（适配层，M0: 39/36）——**已验收**；**测试条件纪律：电流环阶跃一律堵转**（EXP-03，否则角度延迟伪影 ∝I² 污染 Cd 判读） |
| 模式 | `MT2`（foc_current）+ 力矩模式电流目标阶跃（如 0.1→0.3A，红线：持续 ≤0.5A） |
| 增益初值 | **已定档（TST-01，2026-09-21）：ωc=125 rad/s → kp=0.53、ki=1031**（L=4.25mH、R=8.25Ω，τc=8ms；受主循环 ~1.35kHz 数字上限 ωc≤loop/10 约束）——固件 `WC` 已抄回，后续仅微调 |
| Studio 操作 | 电流 Q/D 页改 `MQP/MQI` 等，曲线窗看 iq 阶跃响应 |
| 判据 | 阶跃跟随、稳态误差达标（T-P1-3），两轮复现 |
| 抄回 | `SimpleFocMotor::init()` 增益处 + 本文档附录登记 + 验收报告 |

#### 速度环（T-P1-6，前置：内环过门并冻结）——级联版（2026-09-21 起）

**级联架构**：速度环踩在冻结电流环上——`MT2 + MC1`，速度 PID 输出即 **Iq 指令**（A 域）进入电流内环；输出限幅 = **0.5A 持续红线**（级联安全钳位，失控也怼不出大电流）。整定台「速度环」预设与 ▶±幅值 发送均自动带上 MT2+MC1（原子模式保证）。

增益（计算优先，R 由内环接管）：kp_v = ωv·J/KT = **0.0025 A/(rad/s)**、ki_v = N×kp；带宽仍 ωv=20 rad/s（旋钮未变，单位域从电压换到电流）。

> **已定档（TST-02，2026-09-21）：N = 10 → ki_v = 0.0254（ζ=½√(ωv/N)=0.707）**，固件 `kiV` 倍率已抄回；随役参数定标 **KT=0.032 N·m/A、J=4.06e-6**（②实测，EXP-04）——kp_v 数值不变（J/KT 比值免疫）。**低速边界 5~10 rad/s**（5 停-走 / 10 平滑，EXP-05 三重塌方），验收范围 ≥10 rad/s。
> **纪律：参数写入后必须读回或看 [VEL DBG] 探针 P=/I= 确认**——整定台参数卡显示的是上位机本地对象值，不构成固件已写入的证据（EXP-04 案：首轮"N=10 失败"实为 N=5）。

> 电压域旧版（MT0+MC1，kp=0.021/ki=0.105，复现官方基线 0.021/0.12）为对照历史存档——J 的反推估算（③类）来自该基线，与域无关，继续有效。

| 步骤 | 内容 |
|---|---|
| 模式 | 整定台点「速度环」（自动 MT2+MC1）或直接 ▶±幅值（原子模式自动带上） |
| 判据通道 | Vel 曲线；Vq 曲线看内环输出（不应贴 0.5A 对应电压） |
| 验收 | 固件模式指示绿灯（速度/FOC电流）；**≥10 rad/s 平滑跟踪（TST-02）**；5~10 rad/s 停-走边界带（机制见 EXP-05，不判失败）；写入后必读回/看探针（EXP-04） |
| 抄回 | `.ino` WV 常数 + 本文档登记 |

**2026-09-21 失控案教训（已根治）**：目标落在力矩模式被解释为恒压（力矩电压模式 Vq 直通无钳位）→ 自由加速。三重防线：① sendTarget 原子重发 MT+MC；② 读数区固件模式指示（不符标红）；③ 级联后 PID 限幅 0.5A 物理钳位。

#### 位置环（T-P1-7，前置：速度环过门并冻结）——级联版（2026-09-21 起）

- **开工前置检查（必做）**：整定台「位置环」预设发送 **MT2+MC2**（踩冻结速度环，速度预设同款级联），连接后**看模式指示灯须为 位置/FOC电流**——2026-09-21 案：预设曾遗留电压域（torque=0），固件如实执行 MT0、指示灯对"预设意图"绿灯，位置环踩在域错配速度环上跑出张弛振荡（P 项 0.0025V 形同虚设、积分+2V 天花板→~60 rad/s 飞摆），"P=4 大过冲"为假象。教训：**守卫验证执行忠实度，不验证意图正确性**；开工拦截必须写在剧本里，不能留在记忆中；
- 增益：单旋钮 **ωp = kpP = ωv/5 = 4 [1/s]**（P-only：type-1 环阶跃 ess=0、内环积分扛恒载，不加 I；D 治动能过冲但先试 velocity_limit 软限速）；官方 P=20=零分离比激进档，仅作对照；
- 激励：**0→±π/2 单步**（阶跃前稳在 0，两步间隔 ≥3s）或慢方波（**period ≥4s**，一拍=瞬态 ~1s+稳态 ≥3s）——快速翻转的全反转阶跃（3+ rad）激发动能/fling 过冲，不能用于给 P 定性；
- 判据：通用（tr/ts/σ%/ess，Angle 响应通道）+ 位置专属（**稳态带 ±0.1 rad 驻留**、终值段峰峰值——穿停-走区代价、到位重复性）；终值段爬行为速度环低速边界的正常投影（EXP-05）；
- 路径 B（路线暂缓）：中间件 PositionNode，库代码保留，待 P4 评估。

## 5. 使用流程（操作手册）

### 5.1 连接 SOP（零配置版，2026-09-20 起）

1. **烧录**唯一主程序 `examples/FocKit_commissioning`（已内置 StudioBridge）；
2. **接 12V**，等串口打印「电源就绪」「三环整定主程序就绪」——**顺序不能反**：`PowerMonitor::waitReady()` 在母线电压未达阈值时会阻塞且不读串口，此时上位机连接必然 Write timeout；
3. **启动 Studio**（`Start-SimpleFOCStudio.cmd`）——设备页**自动打开**，不再需要「文件 → 打开设备」；
4. **选端口、点连接**：连接区下拉框选 COM 口（上次用过的端口自动回选）→ 点「连接」。未选端口会弹提示；下拉列表为空时先确认板卡已通电、驱动已装好，再点开下拉刷新；
5. **验收**：参数不全零、曲线窗有数据、改参生效；
6. **结束**：关上位机即可；固件退出会话按板上 EN/RST 复位。

写死的链路参数（不可改、也无需改）：命令前缀 `M`、115200-8N1、拉取模式。「文件 → 打开设备」保留，仅用于载入历史整定值 JSON（不再影响串口字段）。串口独占：连接前关闭 Arduino IDE 串口监视器等占用程序。

### 5.2 三个「填了也不生效」的坑（历史档案，已随零配置改造根除）

> **状态（2026-09-20）**：三坑同根同源（前缀依赖界面/文件配置），零配置改造后**全部根除**——前缀写死、命令ID 输入框删除、连接不再依赖「打开设备」。下表保留作故障史档案：当年每个坑都真实踩过并各自修过一轮，最终以"写死"收口。

### 5.3 链路异常时的 30 秒自证（回归检查）

> 前缀写死后本节理论上不再触发，保留作回归自证：若链路再次异常，先看这里排除上位机侧。

`src/simpleFOCConnector.py` 的 `[SERIAL TX] … command=…` 是**触发型**打印，始终同时上控制台并落盘 `.SimpleFOCConfigTool.log`（Studio 工作目录）。看这一行即可判定下行命令是否正常：

| 日志内容 | 判定 | 处理 |
|---|---|---|
| `command='MMG0'` | 前缀正常，问题在别处（查 §5.1 第 2 步电压/阻塞） | — |
| `command='MG0'` | 前缀为空串——写死后属**源码回归**（构造函数被改回 `''` 或出现新写点） | 检查 `simpleFOCConnector.py` 的 `devCommandID` 初始化与写点 |

需要更细的链路证据时，用环境变量打开冗长打印（默认只落盘）：

```bash
FOC_TRACE_VERBOSE=1 python simpleFOCStudio.py
```

- device.json 存有**旧电机的默认参数**（P/I/限幅等是别的电机值）——拉取模式下连接后以固件实际值为准，勿手抄界面初始值；

### 5.5 SimpleFOC 2.2.1 本地补丁与固件硬化（2026-09-20，"绘曲线即死"根治）

**现象**：绘图勾选 Cq/Cd（曲线变量含电流位）后固件瞬间全哑——无心跳、无应答、曲线残行断在第 3 列（Vd 之后，恰是 `monitor()` 内调 `getFOCCurrents()` 之前），复位后复现。降采样 100/1000 无差别 → 与串口流量无关（实证排除带宽说）。

**根因**：两套 ADC 驱动打架。电流采样走库自带裸寄存器驱动 `adcRead()`（`esp32_adc_driver.cpp`，把 ADC1 强占为软件控制模式），母线检测 `dengfoc_v4::readVin()` 走 arduino-esp32 2.0.4 官方驱动 `analogReadMilliVolts()`（每秒一次）。两驱动交替接管后 SAR 转换完成标志不再置位，`__adcEnd()` 的 busy-wait **死循环卡死主循环**。触发面精确闭合：电压力矩模式下 loop() 内唯一调 `adcRead()` 的路径就是 monitor() 的电流列（setup 阶段采样对齐时驱动刚独占初始化，故初始化不受影响）。上游 2.3.x 重写 ESP32 电流采样驱动即为此因。

**修复**（两层，均已落地）：

1. **本地补丁（已安装库，不在 git 内）**：`Documents/Arduino/libraries/Simple_FOC/src/current_sense/hardware_specific/esp32_mcu.cpp` 的 `_readADCVoltageInline` 改用 `analogRead(pinA)`（同为 12bit 0..4095，尺度不变）。⚠️ **重装/升级 SimpleFOC 库会覆盖此补丁**——症状复现先查这里；长期挂账：升级 SimpleFOC 2.3.x 后撤补丁回归验证。
2. **固件硬化（本库工程内）**：`setup()` 加 `Serial.setTxBufferSize(512)`（突发打印入环形缓冲）+ `StudioBridge::update()` 曲线流限速闸（两次 `monitor()` 最小间隔 10ms，硬上限 ~100 行/秒）——无论界面降采样配多小，TX 都打不满 115200、压不住 FOC 主循环。

**排查方法论存档**：三层瓶颈分开证伪——①上位机 GUI（逐行全量重绘，已解耦限频）；②串口链路容量（降采样 1000 仍死即排除）；③固件外设状态（残行断点定位到电流读取调用处）。每层都要有"换个参数就能否决"的判据。

## 6. 纪律与边界

1. **RAM 值纪律**：Studio 改动重启即失——调好必抄回代码（bsp/control 默认值）并在验收记录登记，NVS 只固化编码器标定；
2. **模式切换安全**：Studio 的 `MC` 直通固件、绕过我们的清目标防御——**切模式前目标归零**；P0 阶段只允许 `MT0`；
3. **中间件 PID 不可达**：Studio 整定页只覆盖 SimpleFOC 环；中间件环用 `pid v/p`（增强项挂账 §4.2）；
4. **数据落盘**：整定曲线 Studio 截图 + 我们 `stream` CSV 双轨，落 `06_验证与实验记录/波形与数据/`；
5. **契约**：StudioBridge 之外任何层不得引用 Commander/SimpleFOC 类型。
