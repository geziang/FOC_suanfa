## 1. 选型结论与设计逻辑

**结论**：选定 SimpleFOCStudio（本地 EXE 版运行、zh 源码审计）为本项目套件平台的唯一图形化整定上位机。

设计逻辑：

1. **协议原生匹配**：固件端 SimpleFOC 自带 Commander 电机命令集，Studio 直接说这门语言——固件侧零协议改造，我们只需 StudioBridge 两行接入；
2. **整定刚需全覆盖**：四套 PID 整定页（速度 V、角度 A、电流 Q/D）+ 目标阶跃 + 实时曲线 + 启停控制，正是分环整定的标准动作；
3. **开箱即用且可审计**：EXE 免 Python 环境；zh 源码在手，协议可查证（本文 §2 即源码实证）、必要时可魔改；
4. **被否决的方案**：串口绘图器（只能看不能调）；自研上位机（造轮子，与"不重写 FOC 轮子、专注上层算法"同一条立项理由）。

**边界**：它是**套件平台的工具**。P4 换实验室硬件后，上位机随平台另定（CAN 工具链），届时本文降级为历史参考。

## 2. 协议合同（源码实证）

### 2.1 连接层

| 项 | 行为 |
|---|---|
| 串口参数 | 115200 / 8N1 |
| 握手 | **无**——打开串口即通 |
| 连接模式 | 拉取（连上后把固件当前参数读进界面，**推荐**）/ 推送（把界面参数写入固件）/ 仅连接 |
| 状态轮询 | 连接后每秒发 `MG0~MG6` 刷新状态回显 |
| 命令前缀 | `devCommandID`，device.json 保存为 `'M'`，与固件注册一致（来源链见 §2.1.1） |

### 2.1.1 命令前缀的来源链，与「两个同名框」陷阱（2026-09-20 补）

**为什么单列一节**：这个字段是历史上最耗时的一个坑——上位机界面上有**两个**中文标签都叫「命令ID」，只有一个是真字段。填错的那个不会有任何报错，只是链路整体无声瘫痪（轮询偶通、pull config 全废、参数全零）。

前缀来源链（`src/simpleFOCConnector.py`）：

| 环节 | 事实 |
|---|---|
| 默认值 | `devCommandID = ''`（构造函数） |
| 唯一赋值来源 | `configureDevice()` 从 JSON 的 `devCommandID` 键读取 |
| 谁调用它 | **只有** `workAreaTabbedWidget.openDevice()`（菜单「文件 → 打开设备」） |
| 谁用它 | `sendCommand(devCommandID + 命令体)`（`setCommand`/`getCommand`） |
| 落盘 | `toJSON()` 写回 `devCommandID`；界面手填的值**只活在本次会话** |

⇒ 结论：**只有走「文件 → 打开设备」加载 `device.json`（其 `"devCommandID": "M"` 已就位），才是可靠、可复现的路径。**

两个同名框的鉴别：

| 界面位置 | 控件 | 写入成员 | 是否下发到串口 |
|---|---|---|---|
| 「设置」按钮弹出的 *Configure serial connection* 窗口 | `connectionIDlineEdit`（标签 `连接ID（不下发）`） | `connectionID` | **否**——全库无任何发送路径读取它，纯留档 |
| 「设备」页「连接」按钮旁的 `命令ID:` 输入框 | `devCommandIDLetter` | `devCommandID` | **是**——决定线路前缀 |

> 提示：弹窗那个字段原名 *connection name*，中文翻译成「命令ID」才产生歧义；本机源码已把标签改为「连接ID（不下发）」并加了悬浮说明。

**固件侧兜底（宽容解析，2026-09-20 增）**：即便前缀填错，`StudioBridge::handleLine()` 也会靠两条铁证自动判定本会话约定 —— 见到 `MM…` 判为「已配 ID」，见到非 `M` 打头的命令字母行判为「无 ID」，默认按已配 ID 处理，且随证据自我修正。代价是掩盖配置错误（`dbg on` 时会打印 `handleLine id=stripped/absent` 便于核对），收益是两种约定都能跑。**但这只是兜底，SOP 仍要求填对。**

### 2.2 命令层

**线缆格式 = `<命令ID><命令体>\n`**。下表按**命令 ID = `M`** 的约定直接给出线缆上的字符串（例：`ME1` = ID `M` + 命令体 `E1`；监控量查询因命令体自身以 `M` 开头，线缆上是 **`MMG0`**）；若命令 ID 留空，则线缆上就是去掉了首字符的形态（`E1`、`MG0`）。全部命令体已与固件端 `commands.h`（SimpleFOC 2.2.1）逐条比对一致：

| 功能 | 命令 | 备注 |
|---|---|---|
| 目标值 | `M2.5`（数字直跟） | 目标滑杆 |
| 启停 | `ME1` / `ME0` | |
| 控制模式 | `MC0/1/2` | 0 力矩、1 速度、2 位置（3/4 为开环变体） |
| 力矩类型 | `MT0/1/2` | 0 电压、1 dc_current、2 foc_current |
| 速度环 PID | `MVP` `MVI` `MVD` + `MVR`(ramp) `MVL`(limit) `MVF`(LPF) | 整定页"速度" |
| 位置环 P | `MAP` + `MAR` `MAL` `MAF` | 整定页"角度" |
| 电流 Q 轴 PID | `MQP` `MQI` `MQD` + `MQR` `MQL` `MQF` | 需电流采样（P1 前置） |
| 电流 D 轴 PID | `MDP` `MDI` `MDD` + `MDR` `MDL` `MDF` | 同上 |
| 限幅 | `MLU`(电压) `MLC`(电流) `MLV`(速度) | |
| 相电阻 | `MR<值>` | |
| 监控配置 | `MMD`(降采样) `MMS`(变量掩码) `MMC`(清除) | 连接时 Studio 自动下发 |
| 状态查询 | `MG0~MG6` | 应答目标/角度/速度/vd/vq/id/iq |
| 传感器零位 | `MSM`(机械 offset) `MSE`(电零位) | |
| 调制方式 | `MWC`(居中) `MWT`(0 正弦/1 SVPWM/2,3 梯形) | 我们固定 SVPWM |

### 2.3 数据判定三规则（决定固件输出格式）

上位机对收到的每行按首字符分类（`SerialPortReceiveHandler`）：

| 行特征 | 判定为 | 固件来源 |
|---|---|---|
| 以数字或 `-` 开头 | **绘图数据**（Tab 分隔） | `motor.monitor()` 输出 |
| 含 `Monitor` 字样 | 状态应答 | `MG` 查询的应答 |
| 其余 | 控制台日志 | 各类打印 |

推论：会话期间固件不得往串口打印非协议文本（我们的 shell 已让位，满足）。

## 3. 我们的适配设计

### 3.1 StudioBridge（adapter 层）

- `Commander('M' → command.motor 全权委托)`：一条通道覆盖 §2.2 全部命令；
- `monitor_variables = 目标|速度|角度`、`monitor_downsample = 0` 初始静默——连接后 Studio 自己下发 `MMD/MMS` 开流；
- **契约**：Commander/SimpleFOC 类型封闭在 adapter 层，`core/`、`control/` 零感知（P0-⑤ 编译检查）。

### 3.2 shell 让位机制

| 动作 | 方式 |
|---|---|
| 进入会话 | **自动**：shell 读到以大写字母开头、且不在自身命令字白名单里的行（= 上位机协议命令）即置会话态，并把该行转交 `StudioBridge::handleLine()`；手工输 `studio` 仍有效 |
| 会话期 | 串口收发由会话独占，shell 不再插话（不打印 `dispatch raw=`、不回「未知命令」） |
| 退出会话 | 板上复位（EN/RST）——Commander 独占后 shell 听不到命令，复位是最可靠的退出通道 |

让位的原因：两个解析器同读串口会抢字节。

两处易错细节（都在固件侧，改动见 commit `f9b07f1`）：

1. **转交必须补回行尾 `\n`**：Commander 的 `isSentinel()` 靠行尾字符判 GET/SET，而 shell 行缓冲里没有换行符；漏补会把「读」变成「写 0」（`MQP` → 参数被清成 0），是危险错误。
2. **非本会话 ID 的行静默丢弃**：`handleLine` 不认领的行直接丢，绝不回「未知命令」——这条洪流曾把串口每秒刷掉 20 行。

> 自动接管不可逆：会话态只能靠复位退回；一串纯噪声的大写行也可能触发接管（判别依据见 `SerialShell::isShellCommand_` 白名单）。

## 4. 与项目需求的结合

### 4.1 总表

| 项目需求 | 上位机角色 |
|---|---|
| P0-⑥ 通道验证 | 连接、出曲线、改参生效即验收 |
| **P1 三环整定（最近需求）** | 分环整定主工具（§4.2） |
| P2 力控整定 | 激励施加 + 曲线观测 |
| P4 组合适配 | 不适用（套件专属，实验室平台另定） |

### 4.2 三环整定操作剧本（P1，对齐 SPEC-T T-P1-3/6/7）

**载体程序**：`examples/FocKit_commissioning`（examples 下唯一主程序）——建模带宽计算区（开机即算即打印增益）、`loop t|v|p|i` 一键进会话、`step` 自动方波激励。计算链（计算优先，参数来源优先级见 SPEC-T §1）：**建模 → 取标称 → 选带宽 → 公式算增益 → Studio 在计算值附近微调 → 抄回**。

**每环统一节奏**：前置检查 → 模式设置 → 增益初值（公式算，不扫参）→ 阶跃激励 → 判据核对 → 抄回代码 + 落盘。

#### 电流环（T-P1-3，前置：电流采样接入）

| 步骤 | 内容 |
|---|---|
| 前置 | T-P1-2 板载电流采样接入（适配层，M0: 39/36）——**未接入前 MT1/MT2 不可用，此剧本不适用** |
| 模式 | `MT2`（foc_current）+ 力矩模式电流目标阶跃（如 0.1→0.3A，红线：持续 ≤0.5A） |
| 增益初值 | kp = L/τc ≈ 4.25、ki = R/τc ≈ 8250（L=4.25mH、R=8.25Ω 已闭环，τc 取 1ms）——**先抄初值再连 Studio 微调** |
| Studio 操作 | 电流 Q/D 页改 `MQP/MQI` 等，曲线窗看 iq 阶跃响应 |
| 判据 | 阶跃跟随、稳态误差达标（T-P1-3），两轮复现 |
| 抄回 | `SimpleFocMotor::init()` 增益处 + 本文档附录登记 + 验收报告 |

#### 速度环（T-P1-6，前置：内环过门并冻结）

双路径，先说清区别再选：

| 路径 | 谁 | 工具 | 用途 |
|---|---|---|---|
| A 内置对照组 | SimpleFOC 速度环 | Studio `MC1` + 速度 PID 页（官方基线 MVP=0.021/MVI=0.12 起步） | 快速验证通道、给中间件环提供参照系 |
| B 中间件环（**路线暂缓**） | 本库 VelocityNode（库代码保留于 `src/control/`，当前无示例载体） | 原示例 02/03 已随 examples 收敛移除；shell `pid v` 需 attach 节点才生效 | 与 P4 实验室 CAN 硬件移植同步再评估；**Studio 页面够不着这层** |

判据（两条路径同）：速度阶跃指标（建立时间/超调/稳态误差）达标且两轮复现（T-P1-6）；当前只走路径 A；若重启路径 B，其指标数据来自 `stream` 采样，落 `波形与数据/`。
挂账增强：中间件 PID 注册进 Commander 命名空间，使 Studio 控制台可调（P1 选项，未立项）。

#### 位置环（T-P1-7，前置：速度环过门并冻结）

- 路径 A：`MC2` + 角度页（`MAP` 起步 20）；
- 路径 B（路线暂缓）：中间件 PositionNode + `pid p kp ki kd`，原示例 03 已移除，库代码保留，待 P4 移植阶段评估；
- 判据：±π/2 rad 方波阶跃收敛、稳态 ±0.1 rad 内、超调可整定（同 P0-⑦ 判据）。

## 5. 使用流程（操作手册）

### 5.1 连接 SOP（按序执行，不要跳步）

1. **烧录**唯一主程序 `examples/FocKit_commissioning`（已内置 StudioBridge）；
2. **接 12V**，等串口打印「电源就绪」「三环整定主程序就绪」——**顺序不能反**：`PowerMonitor::waitReady()` 在母线电压未达阈值时会阻塞且不读串口，此时上位机连接必然 Write timeout；
3. **加载设备配置**：SimpleFOCStudio →「文件 → 打开设备」→ 选 `device.json`（含 `devCommandID: "M"`）；
4. **核对命令前缀**：打开「设备」页，看「连接」按钮旁 `命令ID:` 框里是否显示 `M`。**显示空串就说明第 3 步没生效，先停下**；
5. **连接**：选 COM 口、115200、连接模式选**拉取（Pull config）** → 点「连接」。固件侧会自动让位进会话，无需先手工输 `studio`；
6. **验收**：参数不再全零、曲线窗有数据、改参生效；
7. **结束**：关上位机即可；固件退出会话按板上 EN/RST 复位。

### 5.2 三个「填了也不生效」的坑（同一根因家族，都踩过）

| # | 现象 | 根因 | 现在的处理 |
|---|---|---|---|
| 1 | 在「设置」弹窗里填了「命令ID」，毫无作用 | 该框绑的是 `connectionID`，全库无发送路径读取（见 §2.1.1） | 已把标签改为「连接ID（不下发）」并加悬浮说明 |
| 2 | 在「设备」页填了 `M`，还是不通 | 该框原以 `editingFinished`（回车/失焦）提交，**打了字不回车不算数** | 已改为 `textChanged` 即时提交 + `maxLength(1)` + 自动去空白 |
| 3 | 「文件 → 打开设备」点了没反应、没弹窗 | 原实现整个函数体都套在 `if configDeviceTool is None` 里：**已有「设备」页时静默 no-op** | 已有「设备」页时改为弹窗明确提示（请先关闭该页） |

附带两条易忘事实：

- `devCommandID` **不随会话持久化**：界面手填的值只活在本次会话，重启 Studio 即回到 `device.json` 的值（或空串）；
- 「设备」页那个框的显示值就是判据：走对了「打开设备」，它一定自动填上 `M`。

### 5.3 连不上时的 30 秒自证

`src/simpleFOCConnector.py` 的 `[SERIAL TX] … command=…` 是**触发型**打印，始终同时上控制台并落盘 `.SimpleFOCConfigTool.log`（Studio 工作目录）。看这一行即可判定前缀是否生效：

| 日志内容 | 判定 | 处理 |
|---|---|---|
| `command='MMG0'` | 前缀已生效，问题在别处（查 §5.1 第 2 步电压/阻塞） | — |
| `command='MG0'` | 前缀为空串，下行命令缺位 | 回到 §5.1 第 3、4 步 |

需要更细的链路证据时，用环境变量打开冗长打印（默认只落盘）：

```bash
FOC_TRACE_VERBOSE=1 python simpleFOCStudio.py
```

### 5.4 其余注意事项

- device.json 存有**旧电机的默认参数**（P/I/限幅等是别的电机值）——拉取模式下连接后以固件实际值为准，勿手抄界面初始值；
- 串口独占：连接前关闭 Arduino IDE 串口监视器及其他占用程序；
- 同一时刻只连一个上位机/终端。

## 6. 纪律与边界

1. **RAM 值纪律**：Studio 改动重启即失——调好必抄回代码（bsp/control 默认值）并在验收记录登记，NVS 只固化编码器标定；
2. **模式切换安全**：Studio 的 `MC` 直通固件、绕过我们的清目标防御——**切模式前目标归零**；P0 阶段只允许 `MT0`；
3. **中间件 PID 不可达**：Studio 整定页只覆盖 SimpleFOC 环；中间件环用 `pid v/p`（增强项挂账 §4.2）；
4. **数据落盘**：整定曲线 Studio 截图 + 我们 `stream` CSV 双轨，落 `06_验证与实验记录/波形与数据/`；
5. **契约**：StudioBridge 之外任何层不得引用 Commander/SimpleFOC 类型。
